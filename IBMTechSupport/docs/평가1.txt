1. RAG V3 설정 동결 및 실제 평가 코드 반영 [완료]
================================================================

1-1. 최종 선택
- RAG V3는 Stage2 Retrieval + Answerability Judge 프롬프트 V3이다.
- 기존 configs/rag/v3.yaml 및 Stage3 Retrieval과는 다른 구성이다.
- 기존 Stage2 Generator와 Grounding Verifier는 변경하지 않았다.
- 이전 실험에서 정답성보다 근거 충실도 및 답변 불가능 질문의 거부를
  우선하여 V3를 선택했다. 모든 지표에서 우월한 모델이라는 뜻은 아니다.
- 별도의 평가용 Judge v3.13 설정도 기존 동결 상태를 유지한다.
  아래 Answer Correctness / Faithfulness는 별도 Stage2 품질 평가 프롬프트와
  Qwen2.5-1.5B-Instruct로 계산한 자동 판정이며 v3.13과 구분한다.

1-2. 동결 설정
- Retrieval: Stage2, BM25 + Dense Weighted RRF
- Embedding: BAAI/bge-small-en-v1.5
- FAISS: HNSW, 벡터 111,023개
- PCA: 384 -> 192차원
- HNSW M=32, efSearch=128, FAISS CPU threads=4
- 제품/버전/CVE/APAR/오류 코드 Soft Filter: ON, strength=1.0
- Reranker: cross-encoder/ms-marco-MiniLM-L6-v2
- Reranker Candidate K: 10
- Query Rewrite: OFF
- Judge Mode: per_document_v3
- Top K: 5, Retry Top K: 10
- Base / Generator / Runtime Judge / Grounding Verifier: Qwen2.5-1.5B-Instruct
- Generation: batch_size=1, max_new_tokens=160, do_sample=False, num_beams=1
- 원본 Stage2 설정: configs/rag/v5_stage2_106.yaml
- 최종 동결 설정: configs/rag/stage2_v3_frozen.yaml
- 선택된 Retrieval 설정: configs/rag/retrieval_stage2_selected.yaml

처리 순서:
  질문 -> Hybrid Search -> Soft Filter -> Reranker -> Top5 개별 청크 Judge
  -> YES 청크가 없으면 6~10위 추가 Judge
  -> YES 청크만 Generator에 전달 -> Grounding Verifier
  -> 검증 YES면 답변 반환, 그 외 거부
  -> YES 근거가 없으면 생성하지 않고 거부

================================================================

2-2. 공통 학습 설정 (LoRA / QLoRA)
- Train 632건, Validation 106건
- Rank=8, Alpha=16, Dropout=0.05
- Target Modules: q_proj, v_proj
- Learning Rate: 2e-4
- Epochs: 2
- Max Length: 512
- Max Question Tokens: 192, Max Answer Tokens: 160
- Batch Size: 1, Gradient Accumulation: 8
- Optimizer: AdamW, Gradient Clipping: 1.0
- Gradient Checkpointing: ON, 학습 중 KV Cache: OFF
- Compute Precision: FP16, GradScaler 사용
- Seed: 42
- 질문/프롬프트 토큰은 labels=-100으로 Loss에서 제외.
- Answerable은 reference answer, Impossible은 거부 문자열을 target으로 사용.

LoRA는 FP16 Base 가중치를 고정하고 Adapter만 학습한다.

     - 샘플 평균 Loss / 토큰 평균 Loss의 실제 학습 영향 비교.
     - Answerable / Impossible별 Loss 기록.
4-3. 클래스별 학습 가중치 및 샘플링 조정 실험
4-4. Learning Rate 최적화
4-5. LoRA Rank / Alpha 최적화
4-6. Target Modules 최적화
4-7. Epoch 및 체크포인트 선정 기준 개선
     - Loss뿐 아니라 Token F1, Answer Correctness, 거부율 함께 확인.
4-8. LoRA / QLoRA 재학습 및 동일 Validation 평가
4-9. 최적 설정 선정 및 동결

원칙:
- 기존 결과 및 설정을 덮어쓰지 않고 실험별 경로에 저장.
- 가능한 한 한 번에 하나의 설정을 변경하여 영향 확인.
- 106건 Validation 기준으로만 최적화하며 새 독립 Test는 8단계에서 사용.
- Smoke Test는 생략.
- 위 최적화 순서는 계획이며 아직 실행하지 않았다.

6. 이후 6개 모델 비교 계획
================================================================
1) Base LLM
2) Base LLM + RAG V3
3) LoRA
4) QLoRA
5) LoRA + RAG V3
6) QLoRA + RAG V3

공통 평가 지표:
- Exact Match, Token F1, Answer Correctness
- 올바른 거부율, 잘못된 거부율
- Inference Latency, Peak GPU Memory

RAG 전용 평가 지표:
- Hit@5, Recall@5, Precision@5, MRR@10, nDCG@5
- Faithfulness
- 비검색 모델은 N/A 처리.

정의:
- Answer Correctness: 엄격한 CORRECT 판정 수 / 전체 Answerable 질문 수.
- Faithfulness: 모든 중요 기술 주장이 실제 Generator 입력 근거로
  지지된 답변 수 / 실제 반환한 답변 수 (답변 단위).
- 올바른 거부율: Impossible 중 거부한 비율.
- 잘못된 거부율: Answerable 중 거부한 비율.
- 기존 품질 평가 함수와 동일한 평가 모델을 유지.
- 자동 판정 결과를 사람의 검증을 거친 실제 정확도로 간주하지 않음.
- 최종 비교에서는 공통 데이터, decoding, batch size 및 시간/메모리
  측정 범위를 통일하고 모델별 필요한 양자화 및 RAG 차이를 명시.
