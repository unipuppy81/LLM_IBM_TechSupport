2. Evidence Judge 오류 분석 및 최적화

Evidence Judge가 검색된 문서를 YES/NO로 판단하는 기준(프롬프트)을 변경하고, 
어떤 기준이 실제 RAG 성능에 유리한지 비교하는 작업 진행


기존 Hybrid + Reranker 검색 결과
135개 질문 × Top 5 = 총 675개 청도

이거를
Baseline	각 청크 YES/NO
Balanced	각 청크 YES/NO
Strict		각 청크 YES/NO


프롬프트는 어떤 기준으로 나눴는가?	
프롬프트	판단 기준										실험 목적
Baseline	기존 서비스의 YES/NO 기준							비교 기준점
Balanced	질문의 핵심을 충족하면 YES. 표현 차이나 부수적인 			과도한 거부 감소
		조건 때문에 무조건 거부하지 않음						
Strict		제품, 오류, 버전, 핵심 조건에 대한 충분한 근거가 있어야 YES	근거 없는 답변 감소


예를 들어 사용자가 특정 IBM 오류의 해결 방법을 질문했을 때:
- Balanced: 동일 오류의 해결 절차가 확인되면, 질문과 문서의 표현이 달라도 YES를 허용
- Strict: 오류가 비슷하다는 이유만으로는 YES를 허용하지 않고, 실제 적용 조건까지 확인
두 프롬프트 모두 근거가 없으면 NO입니다. 차이는 충분한 근거를 인정하는 판단 기준
